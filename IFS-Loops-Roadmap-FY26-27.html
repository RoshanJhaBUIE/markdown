What Sets IFS Loops Apart

Unlike monolithic agents that bolt an LLM onto a workflow, a Loops Digital Worker is built on a dual-model architecture
with a fine-tuned planning orchestrator, a three-layer memory model, and pattern-based determinism.

Planning Orchestrator
Fine-tuned 8–13B model

A domain-trained orchestrator sequences tool calls and skills. Planning is correct, not merely plausible — variability is treated as a defect, unlike single-LLM agents.

Sequences Skills Domain-Specific
Three-Layer Memory
Episodic · Semantic · Procedural

Memory is persistent, queryable and owned by the organisation — not stuck in one model’s context. Knowledge compounds and never leaves with an employee.

Institutional Memory Org-Owned
Determinism
Recognition over reasoning

The orchestrator recognises a known pattern class and instantiates it, rather than reasoning from first principles each time — how determinism enters an agentic flow.

Pattern Library Auditable
A Division of Labor Others Skip
Planning Intelligence
Understands workflow state, selects defined actions, sequences steps by dependency, and anticipates failure modes. Benefits from domain specificity, not general fluency.
Fine-Tuned Must Be Correct
Generative Intelligence
A large general model (OpenAI / Anthropic) extracts structure from voice, video and documents, and produces human-quality output — freed from the burden of planning.
Unstructured Input Fluent Output
Collaborative Reinforcement
When an expert overrides an action, the why becomes training data. Successful patterns strengthen; failures weaken. Expertise is retained when people leave.
Expert Coaching Improves w/ Use

Data Residency
Data stays within its region, with cross-border transfer controls and daily encrypted backups.
Customers choose their data residency region at onboarding. Data — including model context, work orders, and agent logs — never crosses regional boundaries without explicit configuration. Daily encrypted backups are taken and stored within-region. Cross-border transfers, where applicable, are governed by standard contractual clauses (SCCs).

Annual third-party penetration tests are conducted and findings tracked to resolution. All compliance controls are continuously monitored via Drata with real-time evidence collection.

3 · Connectivity Options

Applies to Private / Customer Cloud and IFS On-Premise deployments only — IFS Cloud uses a direct managed connection
🔒
IP Whitelisting
The IFS endpoint accepts traffic only from Loops' known egress IP addresses. Simplest model — requires no extra infrastructure.
Who configures
Customer IT/Network team whitelists Loops' public egress IPs on the IFS endpoint
Simplest No infra required Private Cloud
↔
Reverse Proxy
Connection is routed through a customer-managed reverse proxy that fronts the IFS environment. Good for environments where direct IP whitelisting is not permitted.
Who configures
Mostly customer configuration — handled by the customer's IT/Network team
Customer-managed Private Cloud / On-Prem
🔐
Site-to-Site VPN
An encrypted network tunnel is established between Loops AWS and the customer's network. Most secure model — used for strict on-premise or air-gapped environments.
Who configures
Joint setup — requires customer IT/Network team and Loops IT team working together
Most secure On-Premise / Air-gapped
